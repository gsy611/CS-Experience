# 通过搜索进行问题求解
## 1.什么是“搜索问题”

一个搜索问题=6个要素
1.状态空间-所有可能的状态集合
2.初始状态-从哪里开始
3.目标状态-什么算成功
4.动作-在某个状态下能做什么
5.转移模型-如果在状态s做动作a，会到哪里,形式：Result(s,a) → s'
6.动作代价-这个动作“贵不贵”

## 2.状态空间vs搜索树

状态空间:描述世界本身,表示所有可能状态,状态之间的连接关系是客观存在的
比如城市地图：
城市 = 状态
道路 = 连接
例子：
A —— B —— C
|    |
D —— E
A,B,C,D,E = 状态
线 = 可以走的路径
这整个结构就是状态空间图,它描述的是世界长什么样
搜索树:描述搜索过程,同一个状态可以在树里出现多次

搜索=在状态空间图上展开一棵搜索树

## 3.为什么要避免“重复路径”和“循环”？
同一个状态可以通过很多路径到达,有些路径更差甚至会来回绕圈
这些叫循环
解决思路：
1.记住已到达状态（图搜索）:来过的地方记下来，不再走第二次
怎么做？
用一个集合（set / hash table）记录reached = {已访问状态}
每生成一个新状态，如果在 reached里，不再展开，不在，加进去继续搜索
2.完全不记（树搜索）
“完全不记路，走到哪算哪”
怎么做？
每条路径都当成全新的,即使状态一样，也当作不同
3.折中：只防循环:只记当前路径，别走回头路
怎么做？
只记录当前路径上的状态,新状态如果已经在当前路径中不回头，但可能还是重复
举例:
当前路径：A → B → C
如果下一步想回到 A:A → B → C → A,不可以，因为 A 已经在当前路径
这样就避免：A → B → C → A → B → C → ...的循环


## 4.搜索算法在比什么？ 
4个指标：
1.完备性：有解一定能找到？
2.最优性：找到的是不是最便宜的解？
3.时间复杂性：要探索多少节点？
4.空间复杂性：要用多少内存

## 5.无信息搜索
定义：完全不知道“离目标近不近”
1.广度优先搜索（BFS）
思想：一层一层往外扩
特点：完备,也就是说只要有答案，BFS最终一定会找到；动作代价相同；内存爆炸（O(b^d)
2.一致代价搜索（Dijkstra）
思想：先走当前代价最小的路径
特点：完备；总是最优；可能探索非常多低代价路径
3.深度优先搜索（DFS）
思想：一条路走到黑，再回退
特点：内存小；可能陷入无限路径；不最优；不一定完备
4.深度受限搜索
思想：DFS + 最大深度限制
也就是说DFS 本来是一直往下走，现在规定最多只能走到深度 L，如果到达 L 层就停止继续往下扩展
问题：深度选不好就会找不到解
5.迭代加深搜索（IDS）
思想：先试深度0，再试深度1,再试深度 2……
优点=DFS+BFS的优点合体：内存小，完备，动作代价相同
