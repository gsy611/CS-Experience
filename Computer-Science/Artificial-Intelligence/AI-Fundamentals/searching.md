# 通过搜索进行问题求解
## 什么是“搜索问题”

一个搜索问题=6个要素<br>
1.状态空间-所有可能的状态集合<br>
2.初始状态-从哪里开始<br>
3.目标状态-什么算成功<br>
4.动作-在某个状态下能做什么<br>
5.转移模型-如果在状态s做动作a，会到哪里,形式：Result(s,a) → s'<br>
6.动作代价-这个动作“贵不贵”<br>

## 状态空间vs搜索树

状态空间:描述世界本身,表示所有可能状态,状态之间的连接关系是客观存在的<br>
比如城市地图：<br>
城市 = 状态<br>
道路 = 连接<br>
例子：<br>
'''text
        A —— B —— C
        |    |
        D —— E
'''<br>
A,B,C,D,E = 状态<br>
线 = 可以走的路径<br>
这整个结构就是状态空间图,它描述的是世界长什么样<br>
搜索树:描述搜索过程,同一个状态可以在树里出现多次<br>

搜索=在状态空间图上展开一棵搜索树<br>

## 为什么要避免“重复路径”和“循环”？
同一个状态可以通过很多路径到达,有些路径更差甚至会来回绕圈<br>
这些叫循环<br>
解决思路：<br>
1.记住已到达状态（图搜索）:来过的地方记下来，不再走第二次<br>
怎么做？<br>
用一个集合（set / hash table）记录reached = {已访问状态}<br>
每生成一个新状态，如果在 reached里，不再展开，不在，加进去继续搜索<br>
2.完全不记（树搜索）<br>
“完全不记路，走到哪算哪”<br>
怎么做？<br>
每条路径都当成全新的,即使状态一样，也当作不同<br>
3.折中：只防循环:只记当前路径，别走回头路<br>
怎么做？<br>
只记录当前路径上的状态,新状态如果已经在当前路径中不回头，但可能还是重复<br>
举例:<br>
当前路径：A → B → C<br>
如果下一步想回到 A:A → B → C → A,不可以，因为 A 已经在当前路径<br>
这样就避免：A → B → C → A → B → C → ...的循环<br>


## 搜索算法在比什么？ 
4个指标：<br>
1.完备性：有解一定能找到？<br>
2.最优性：找到的是不是最便宜的解？<br>
3.时间复杂性：要探索多少节点？<br>
4.空间复杂性：要用多少内存<br>

## 无信息搜索
定义：完全不知道“离目标近不近”<br>
1.广度优先搜索（BFS）<br>
思想：一层一层往外扩<br>
特点：完备,也就是说只要有答案，BFS最终一定会找到；动作代价相同；内存爆炸（O(b^d)<br>
2.一致代价搜索（Dijkstra）<br>
思想：先走当前代价最小的路径<br>
特点：完备；总是最优；可能探索非常多低代价路径<br>
3.深度优先搜索（DFS）<br>
思想：一条路走到黑，再回退<br>
特点：内存小；可能陷入无限路径；不最优；不一定完备<br>
4.深度受限搜索<br>
思想：DFS + 最大深度限制<br>
也就是说DFS 本来是一直往下走，现在规定最多只能走到深度 L，如果到达 L 层就停止继续往下扩展<br>
问题：深度选不好就会找不到解<br>
5.迭代加深搜索（IDS）<br>
思想：先试深度0，再试深度1,再试深度 2……<br>
优点=DFS+BFS的优点合体：内存小，完备，动作代价相同<br>


# 复杂环境中的问题求解
## 局部搜索与最优化问题（核心思想）
1.什么是局部搜索（Local Search）<br>
特点：<br>
    • 只保存当前状态(current state)<br>
    • 只看邻居状态(neighbor state)<br>
    • 不记录路径、不记访问过的状态<br>
适合场景：<br>
    • 只关心最终解（如8皇后、布局、调度）<br>
    • 状态空间非常大或无限<br>
    • 内存受限<br>
类比：在一张“高低起伏的地形图”上走路，只看脚下和附近，找最高峰或最低谷, 而不是规划整条路线。<br>
2.最优化问题（Optimization Problem）<br>
不是“能不能到达目标”，而是最大化目标函数: 让某个数值 越来越大 → 爬山算法（Hill Climbing）<br>
算法做的事：<br>
当前点<br>
 ↓<br>
看看附近<br>
 ↓<br>
往更高的地方走<br>
 ↓<br>
重复<br>
直到走不上去<br>
最小化代价函数：让错误或成本 越来越小 → 梯度下降（Gradient Descent）<br>

## 爬山搜索（Hill Climbing）
- 核心思想:每一步都走向“看起来最好”的邻居<br>
    • 只选当前邻居中值最大的<br>
    • 一旦附近没有更好的→ 停止<br>
- 类比：大雾中爬山，只往“感觉更高”的方向走<br>
- 用8皇后解释<br>
    • 状态：棋盘上8个皇后的位置（每列一个）<br>
    • 启发式函数h：互相攻击的皇后对数<br>
    • 目标：h = 0<br>
- 爬山法：<br>
    • 每次移动一个皇后<br>
    • h变小（攻击更少）<br>
- 1.什么是「8 皇后问题」？<br>
规则:在一个8×8 的国际象棋棋盘上放 8 个皇后，任意两个皇后都不能互相攻击,皇后可以攻击同一行,同一列,同一对角线,只要在这些方向上，就算“互相攻击”。<br>
目标:找到一种摆放方式，使没有任何一对皇后互相攻击<br>

- 2.为什么用8皇后来讲「爬山搜索」？<br>
因为：<br>
    • 解空间很大<br>
    • 不适合暴力穷举<br>
    • 很适合用“一步一步变好”的思想来讲解<br>

- 3.在爬山搜索中，8皇后是怎么表示的？<br>
    1.状态（State）是什么？<br>
    为了简化问题，我们固定规则：每一列恰好放1个皇后<br>
    这样：<br>
    • 不会有“同列攻击”<br>
    • 状态只需要描述每一列的皇后在哪一行<br>
    例如：[1, 5, 8, 6, 3, 7, 2, 4]<br>
    意思是：<br>
    • 第 1 列 → 第 1 行<br>
    • 第 2 列 → 第 5 行<br>
    • …<br>
    • 第 8 列 → 第 4 行<br>
    这就是一个「状态」。<br>
    2.启发式函数h是什么？<br>
    在爬山搜索里，需要一个“好坏评价标准”。<br>
    这里定义：h=互相攻击的皇后“对数”<br>
    • h越小 →状态越好<br>
    • h=0→完美解（没有冲突）<br>
    例子：<br>
    • h=5：有5对皇后在互相攻击<br>
    • h=0：找到解<br>
    3.邻居（Neighbor）是什么？<br>
    邻居=只做一个小改变的状态<br>
    在8皇后中：<br>
    • 一次只移动一个皇后<br>
    • 把它在同一列里换到另一行<br>
    例如：<br>
    • 第3列的皇后从第8行→第4行<br>
    这就生成一个邻居状态。<br>

- 4、爬山搜索在8皇后里怎么“爬”？<br>
算法思想：<br>
    1.随机放8个皇后（每列一个）<br>
    2.计算当前h<br>
    3.看所有邻居：<br>
    • 哪个邻居h最小？<br>
    如果：<br>
    • 有邻居的h更小→ 走过去<br>
    • 所有邻居都不更好→停止<br>
    这就是“只往看起来更高的地方走”<br>

- 5、为什么说它像「大雾中爬山」？<br>
    • 你看不到全局<br>
    • 只能比较：<br>
        ◦ 现在<br>
        ◦ 周围一步能到的地方<br>
    • 可能会卡住在：<br>
        ◦ 局部最优（local maximum / minimum）<br>
        ◦ 明明不是最高峰，但周围都更低<br>
在 8 皇后中可能h≠ 0，但所有移动都会让 h 变大，爬山法就失败了<br>

- 6.8皇后的规则在爬山搜索中“各自负责什么”？<br>

|8 皇后里的东西  |在爬山搜索中扮演的角色|
|--------------|---------------------|
|棋盘 + 皇后     |状态空间（state space）|
|“不能互相攻击”   |目标条件(goal condition)|
|当前摆法        |当前状态(current state)|
|移动一个皇后     |产生邻居状态的规则|
|攻击对数         |启发式函数 h(heuristic function)|
|h = 0           |目标状态（山顶）|

- 7.爬山法的问题（非常重要）<br>
局部极大值（Local Maximum）<br>
    • 附近都更差<br>
    • 但不是全局最优<br>
用爬山比喻：<br>
    • 你爬到一个小山包<br>
    • 四周都是下坡<br>
    • 但远处还有更高的山<br>
岭（Ridge）<br>
    • 必须“先下再上”<br>
    • 贪心算法走不过去<br>
用爬山比喻：<br>
    • 像走山脊<br>
    • 必须：先下一点 → 再上很高<br>
平台（Plateau）<br>
    • 四周都一样<br>
    • 不知道往哪走<br>
算法会卡死（stall）<br>
用爬山比喻：<br>
    • 一大片平地<br>
    • 看不出哪边更高<br>
改进方法<br>
1.允许横向移动（Sideways move）<br>
    • 在平台上先走几步<br>
    • 但要限制次数，否则平地无限走 → 死循环<br>
2.随机爬山<br>
    • 上坡时随机选一个<br>
    • 有概率接受不那么好的<br>
    • 避免太死板，有机会跳出陷阱<br>
3.首选爬山（First-Choice Hill Climbing）<br>
普通爬山Vs首选爬山：<br>
普通 Hill Climbing 做法：<br>
    1. 找出所有邻居状态<br>
    2. 全部比较<br>
    3. 选最好的那个<br>
    4. 移动过去<br>
首选爬山做法：<br>
随机生成一个邻居<br>
↓<br>
如果更好 → 马上移动<br>
↓<br>
否则再随机试一个<br>
不再检查全部邻居！<br>
4.随机重启爬山（最重要）<br>
    • 不行就换个随机初始状态再来<br>
    • 理论上最终一定能成功<br>
做法：
1.随机生成一个初始状态
2.爬山
3.卡住 → 重新随机开始
4.重复多次<br>
结论：爬山法是贪心的局部搜索方法，容易陷入局部极值、岭和平台，因此单独使用不可靠；但结合随机性，尤其是随机重启，可以在实践中高效地解决如 8 皇后等问题，因为只要多试几次可以增加搜索覆盖，随机开始几乎一定能成功<br>

## 模拟退火（Simulated Annealing）
为什么需要它？<br>
    • 纯爬山：太贪心→容易卡局部最优<br>
    • 纯随机：太慢<br>
折中方案<br>
核心思想<br>
    • 一开始：<br>
        ◦ 温度高<br>
        ◦ 允许“走下坡”<br>
    • 后期：<br>
        ◦ 温度降低<br>
        ◦ 越来越像爬山<br>
类比：<br>
晃动乒乓球：<br>
    • 晃得猛 → 能跳出坑<br>
    • 慢慢停 → 留在最低点<br>
本质<br>
    • 以概率接受“变差”的状态<br>
    • 概率：<br>
        ◦ 变差越多 → 越不容易接受<br>
        ◦ 温度越低 → 越不容易接受<br>
结论：模拟退火 = 带概率下坡的爬山法<br>

|特点        |Hill Climbing       |Random Restart Hill Climbing        |Simulated Annealing|
|------------|-------------------|------------------------------------|-------------------|
|基本思想   |一直走向更好状态        |多次重新开始爬山                       |允许偶尔变差|
|是否贪心        |是               |是（每次）                            |非完全贪心|
|接受更差状态    |不允许             |不允许                               |允许（概率）|
|能否跳出局部最优 |很难              |可以                                 |可以|
|方法           |找更高邻居        |卡住就重新随机开始                      |根据温度随机移动|
|随机性          |很少            |中等                                   |很高（初期）|
|内存需求        |很低             |很低                                   |很低|
|搜索范围        |小              |中                                     |大|
|成功率          |低              |高                                     |很高|
|运行方式        |一次搜索         |多次搜索                                |一次但可跳跃|
|典型问题        |简单优化         |8皇后                                   |TSP、复杂优化|

这些算法内存小的共同原因 = “只存当前沿路径的节点，不存整棵搜索树”<br>

## 局部束搜索（Local Beam Search）
思想:同时维护 k 个状态（k 条路径），每一步只扩展最有希望的状态，集中资源在“好状态”上<br>
和随机重启的区别<br>
    • 随机重启：各走各的，互不交流<br>
    • 局部束搜索：好的状态会“吸引资源”，因为好状态 →产生更多后继，被继续探索，搜索力量集中到好方向,各条路径共享当前最优状态信息<br>
风险：k个状态可能挤在一起（缺乏多样性）<br>
    • 随机束搜索：<br>
    • 按概率选，而不是只选最优<br>
    • 保持多样性<br>
例子:<br>
假设搜索树：
'''text
        S
     /  |  \
    A   B   C
   / \     / \
  D   E   F   G
'''
    • 局部束搜索 k = 2<br>
    • 当前层状态 = {A, B, C}<br>
    • 选择评分最高的 2 个状态 → 比如 A、C<br>
    • 下一步只扩展 A 和 C 的后继 → 集中力量在好方向<br>

## 进化算法（遗传算法）
本质一句话:把搜索问题，模拟成“物竞天择，适者生存”<br>
核心要素:              
|要素                        |含义|
|---------------------------|------|
|种群（Population）          |当前同时存在的多个候选解|
|个体（Individual）          |一个具体解，表示一个状态（比如 8 皇后的一种棋盘布局）|
|适应度（Fitness）           |衡量个体质量的指标（比如冲突少的皇后组合更好）|
|选择（Selection）           |根据适应度挑选个体产生下一代|
|杂交（Crossover）           |两个好个体交换部分基因 → 产生新个体|
|突变（Mutation）            |随机改变个体部分基因 → 引入新变化、防止陷入局部最优|

用 8 皇后解释<br>
    • 一个字符串=一个棋盘状态<br>
    • 好的部分（不互相攻击的皇后组合）→会被保留下来<br>
    • 不同好部分可以组合成完整解<br>
关键前提：问题必须能被拆成“有意义的模块”<br>
否则：<br>
1.如果模块没意义 → 杂交没用 → 算法退化成随机搜索<br>
2.8 皇后可以拆 → 杂交有效<br>
3.随机搜索就是没有“适者生存”的版本<br>

## 连续空间中的局部搜索
问题变化<br>
    • 状态不是离散的<br>
    • 而是连续变量（坐标、角度、参数）<br>
例子：<br>
    • 机场选址<br>
    • 神经网络参数<br>
两种方法<br>
- 1.离散化 / 经验梯度<br>
    • 把连续空间切成小格<br>
    • 近似爬山<br>
举例<br>
    1. 机场坐标：x ∈ [0,100], y ∈ [0,100]<br>
    2. 离散化：每 1 km 一格 → 100×100 个候选点<br>
    3. 爬山搜索：每次选择附近格子中收益最大的点<br>

- 2.数学方法（梯度、牛顿法）<br>
1.利用导数<br>
2.梯度方向=最陡上升<br>
梯度是什么？<br>
    • 函数在某点的“斜率向量”<br>
    • 指向：<br>
        ◦ 最陡上升方向<br>
要最小化 → 沿负梯度<br>v
要最大化 → 沿正梯度<br>
直觉理解:你站在山坡上：<br>
    • 梯度 = 哪边最陡<br>
    • 顺着它走 → 最快上/下山<br>
3.牛顿法用二阶信息→更快:<br>
不只看“斜不斜”，还看“弯不弯”<br>
举例:<br>
想象两种情况：<br>
1.坡很直
2.坡很弯（快到谷底）<br>
梯度法：<br>
    • 每次走固定比例<br>
    • 可能走得慢<br>
牛顿法：<br>
    • 根据“弯曲程度”调整步长<br>
    • 更快接近极值<br>
它用的是二阶导数（Hessian矩阵）<br>

|方法                    |梯度来源            |空间类型           |精度                |示例    |
|-----------------------|-------------------|------------------|-------------------|-------|
|Gradient Ascent        |解析梯度            |连续空间           |精确    |神经网络权重优化、函数极值|
|Approximate Gradient   |数值近似梯度     |连续空间 / 离散化       |近似       |黑箱函数优化、实验测量|

都可以应用在连续空间<br>
核心区别 = 梯度是精确公式还是数值近似<br>
问题：<br>
1.高维 → 计算量爆炸<br>
牛顿法需要算Hessian 矩阵<br>
如果 n 维：Hessian 是n × n 的矩阵<br>
举例:<br>
如果 1000 维：1000 × 1000 = 1,000,000个元素<br>
如果 1,000,000 维：1e6 × 1e6 = 1e12个元素 <br>
内存直接爆炸，计算逆矩阵非常慢<br>
所以在神经网络中：<br>
    • 几乎不用牛顿法<br>
    • 用梯度下降（或变种）<br>
2.仍有局部极值问题<br>
看图
     /\      ← 局部最大
    /  \
---/    \____
        /    \
       /      \   ← 全局最大

如果你从左边开始爬山,你会停在那个小山顶<br>
因为：<br>
    • 周围没有更高的点<br>
    • 梯度 = 0<br>
你以为到顶了,但其实还有更高的山。<br>
连续空间也一样,<br>
梯度下降：<br>
    • 只看“附近”<br>
    • 只管当前方向<br>
不会知道，远处还有更低的谷<br>

## 非确定性环境中的搜索
以前的搜索假设是：我做一个动作→世界一定按预期变化<br>
比如：<br>
    • 按开关 → 灯一定亮<br>
    • 往前走 → 一定走到前面<br>
现在变成：同一个动作→可能有多种结果<br>
比如：<br>
    • 吃药 → 可能好转 / 可能没效果<br>
    • 开门 → 可能打开 / 可能卡住<br>
    • 考试 → 可能及格 / 可能不及格<br>
新困难:<br>
1.同一个动作→多种可能结果<br>
2.解不再是“序列”，而是条件规划：<br>
在确定性环境中：解=动作序列（a sequence of actions）<br>
a1→a2→a3→goal<br>
在非确定性环境中：<br>
    • 你不能保证某一步一定成功<br>
    • 必须考虑：<br>
        ◦ 如果成功怎么办<br>
        ◦ 如果失败怎么办<br>
所以解必须是：“条件规划（conditional plan）”：它不是一条直线，它是一个“树”<br>
与或搜索树（AND-OR Tree）<br>
    • OR 节点：我选择哪个动作？<br>
    • AND 节点：这个动作的所有结果都要能应对<br>
解是：一棵子树，而不是一条路径,这棵子树在OR节点选一个动作,在AND节点覆盖所有结果<br>
为什么需要 AND-OR Tree？<br>
在非确定性环境：<br>
    • 一个动作可能产生多个结果<br>
于是出现两种节点：<br>
OR 节点（选择）<br>
含义：我现在该选哪个动作？<br>
因为你可以选：<br>
    • 动作 A<br>
    • 动作 B<br>
    • 动作 C<br>
只需要选一个就够,所以叫OR（或者）<br>
AND 节点（必须全部考虑）<br>
当你选了一个动作之后：这个动作可能有多个结果。<br>
比如：<br>
开门 →<br>
    • 成功<br>
    • 失败<br>
你不能只考虑成功,因为你无法保证哪一个会发生,所以所有结果都必须有后续计划,这就是AND（并且）,意思是成功 AND 失败，两个都必须能处理。<br>
结构长什么样？<br>
例子：
           S0
           (OR)
        /        \
     动作A       动作B
       |           |
      (AND)       (AND)
     /    \      /    \
   S1     S2   S3     S4
解释：<br>
    • 在 S0：选 A 或 B（OR）<br>
    • 选 A 后：可能到 S1,S2（AND）<br>
    • 你必须保证 S1 和 S2 都能到 goal<br>
循环解（反复尝试）<br>
    • 动作可能失败<br>
    • 但多试几次总会成功<br>
例：<br>
    • “一直向右，直到成功”<br>
前提：<br>
    • 失败是随机的<br>
    • 不是永久故障<br>

## 部分可观测环境（信念状态）
- 1.信念状态搜索是处理部分可观测环境的通用方法:<br>
    • 背景：在部分可观测环境里，你不知道自己当前的确切状态。<br>
例如：机器人在迷宫里，烟雾让它看不清自己在哪个格子。<br>
    • 信念状态（Belief State）：是 AI 对“自己可能处于哪些状态”的概率分布或集合。<br>
        ◦ 如果你有 3 个可能格子，概率分别为 0.5、0.3、0.2 → 这就是信念状态。<br>
信念状态搜索就是在信念状态的空间里搜索最优动作，而不是在确定的单个状态里搜索。<br>
搜索的核心思路<br>
    1. 初始信念状态 b0：表示所有可能的初始状态及其概率<br>
    2. 动作更新：执行动作 a ,根据动作模型预测新的信念状态 b′<br>
    3. 观测更新：收到观测后，用贝叶斯公式修正信念状态<br>
    4. 选择动作：在信念状态空间中，选择可以最大化目标概率或期望收益的动作<br>
类比现实生活：<br>
        ◦ 初始猜测 → 我可能在哪<br>
        ◦ 尝试动作 → 我走一步<br>
        ◦ 收到信息 → 看周围环境更新自己位置估计<br>
        ◦ 决定下一步 → 根据信念选择最可能成功的动作<br>
POMDP（Partially Observable Markov Decision Process）：<br>
是数学上对部分可观测环境的严格建模, <br>
部分可观测环境 = POMDP 的实际问题场景<br>
POMDP = 部分可观测环境的数学模型和求解框架<br>
- 2.核心概念：信念状态（Belief State）<br>
我可能在哪些状态中<br>
    • 不确定真实状态<br>
    • 但知道“可能集合”<br>
不是：<br>
    • “我在 A”<br>
而是：<br>
    • “我可能在 {A, B, C}”<br>
- 3.无传感器搜索（Sensorless Search）(无传感器搜索是 POMDP 的特例)<br>
        ◦ 你完全没有感知 → 没有观测信息<br>
        ◦ 信念状态只能通过动作更新<br>
        ◦ 搜索目标：找到动作序列让所有可能状态都到达目标<br>
和一般 POMDP 比较：<br>
|特征                 |一般 POMDP              |无传感器搜索|
|--------------------|-----------------------|------------|
|观测|            有观测，更新信念状态 |       没有观测，只靠动作更新信念状态|
|信念状态更新|    动作 + 观测 → 贝叶斯更新|        仅动作 → 状态集合缩小|
|搜索目标|        最大化期望收益或到达目标概率|     保证所有可能状态都能到目标|

可以理解为：无传感器搜索 = 部分可观测环境的极端情况（观测概率完全为零）<br>
关键点：<br>
    • 在信念状态空间中搜索<br>
    • 状态=状态集合<br>
- 4.重要剪枝思想(Belief State Pruning)<br>
    • 如果一个信念状态是另一个的超集<br>
    • 那么可以丢弃它, 从而有效降低搜索复杂度<br>
原因：“更确定的情况都能解决，没必要管更模糊的”<br>
假设：<br>
    • 信念状态B1={A,B,C}<br>
    • 信念状态B2={A,B}<br>
显然：<br>
    • B2更确定<br>
    • B1更模糊<br>
如果：对更确定的情况B2都能找到解决方案<br>
那么：对更模糊的B1不会更容易<br>
所以：没必要花力气解决“更难的问题，丢弃B1<br>
重要剪枝思想 = 信念状态搜索在部分可观测环境下的优化策略，用来减少搜索空间，提高效率<br>

|非确定性环境                    |部分可观测环境|
|------------------------------|--------------|
|不确定的是动作结果              |不确定的是当前状态|
|AND–OR 树                     |信念状态搜索|
|条件规划                       |集合状态规划|
