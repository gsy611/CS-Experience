# 基于低代码平台的智能体搭建

## Coze
主打零代码/低代码的 Agent 的构建体验,让不具备编程背景的用户也能轻松创造<br>
优势：强大的插件生态系统，直观的可视化编排，灵活的提示词控制，便捷的多平台部署<br>
缺点：不支持MCP,部分插件配置的复杂度高，无法导入编排json文件<br>

## Dify
Dify 是一个开源的大语言模型(LLM)应用开发平台,融合了后端即服务(BaaS) 和 LLMOps 理念,为从原型设计到生产部署提供全流程支持.Dify 支持本地部署(官方提供 Docker Compose 一键启动)和云端部署。用户可以选择将 Dify 自建部署在本地/私有环境(保障数据隐私),也可以使用官方 SaaS 云服务(下述商业模式部分详述)<br>
优势：全栈式开发体验，低代码与高扩展性的平衡，企业级安全与合规，丰富的工具集成能力<br>
缺点：学习曲线较陡，多模态支持不足，API 兼容性问题<br>

## n8n
核心身份是一个通用的工作流自动化平台,而非一个纯粹的 LLM 应用构建工具,有两个最基本的概念：<br>
- Node：节点是工作流中执行具体操作的最小单元，。每个节点都有输入和输出,并提供图形化的配置界面。节点大致可以分为两类:触发节点 (Trigger Node):它是整个工作流的起点,负责启动流程。例如,“当收到一封新的Gmail 邮件时”、“每小时定时触发一次”或“当接收到一个 Webhook 请求时”。一个工作流必须有且仅有一个触发节点；常规节点 (Regular Node):负责处理具体的数据和逻辑。例如,“读取 Google Sheets 表格”、“调用 OpenAI 模型”或“在数据库中插入一条记录”。<br>
- 工作流 (Workflow):工作流是由多个节点连接而成的自动化流程图。它定义了数据从触发节点开始,如何一步步地在不同节点之间传递、被处理,并最终完成预设任务的完整路径。数据在节点之间以结构化的 JSON 格式进行传递,这使得我们可以精确地控制每一个环节的输入和输出。<br>
优势：开发效率高，功能强大且高度集中，支持私有化部署<br>
缺点：内置存储的非持久性<br>
